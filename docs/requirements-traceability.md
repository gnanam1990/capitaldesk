# Requirements traceability

Every functional requirement and core invariant, mapped to the code that implements it and
the tests that prove it, with an honest proof class.

Read the **Proof** column carefully. `unit` and `property` are deterministic reference models
over pure functions. `integration` is a real PostgreSQL server and the real HTTP server.
`browser` is Playwright against the running console. **No row anywhere in this document is
backed by venue evidence, because no Binance account has been contacted.**

Most rows below are `not started`. This is the foundation milestone; the economic core is
M1-M3. A requirement listed as `not started` has no partial implementation hiding behind it.

## Proof classes

| Class         | What it means                                                                                   |
| ------------- | ----------------------------------------------------------------------------------------------- |
| `unit`        | Deterministic test over pure functions                                                          |
| `property`    | Generated cases at a recorded seed, with an independent oracle where the property is arithmetic |
| `integration` | Real PostgreSQL, real HTTP server, real processes                                               |
| `browser`     | Playwright against the running application                                                      |
| `venue`       | Authenticated exchange interaction — **none exists**                                            |
| `gate-only`   | The decision gate is implemented and tested; the producer of the evidence it consumes is not    |

## What "gate-only" means, and why it matters

Several rows are marked `gate-only`. The decision gate is implemented, tested and refuses
correctly; what does not exist is a producer of the evidence the gate consumes. Coverage
cannot reach COMPLETE against a real account because nothing yet proves a movement universe.
No fee policy can dispatch because no pre-trade bound has been derived.

This is the honest state of the milestone. A green run of these tests proves the gate refuses
what it should. It does not prove the product can execute anything, and the code reports
execution as unavailable for exactly this reason.
