# Module 27 — Deployment and restore controls

**Status: PARTIAL**

CapitalDesk now has a pinned multi-stage service image, separate API/worker/executor principals,
external secret mounts, three explicit deployment postures, guarded backup and restore scripts,
and a durable restore command. The executor is excluded from default Compose startup and can
only be selected by the `testnet-write` profile.

## Restore contract

Backup produces a PostgreSQL custom archive and a manifest binding its checksum, immutable
build, environment, migration set and non-secret economic configuration. Restore requires the
exact `HALT_AND_RECONCILE` acknowledgement, refuses a populated target, verifies the checksum,
restores transactionally and enters the existing database restore posture. Old unpublished
outbox work is quarantined; unmarked plans are invalidated; marked attempts remain liabilities.
Authorization recovery accepts only a valid database row or matching external evidence bundle,
otherwise it reports `RESTORE_ATTRIBUTION_UNRECOVERABLE` without inventing FIFO attribution.

## Verification and limits

Unit/static contract tests cover acknowledgement refusal, topology separation and script gates;
shell syntax and a rendered Compose model are checked during this module's targeted validation.
No actual backup/restore rehearsal, clean-image build, rolling migration, external evidence-store
integration, host egress enforcement, image digest/SBOM, CI expansion or deployment is claimed.
