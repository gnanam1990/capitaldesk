# Module 25 — Failure laboratory and conformance evidence

**Status: PARTIAL**

An isolated deterministic scenario runner now covers the nine required fault classes, records
bounded run manifests and exposes a testnet-only one-attempt response-loss transport. The
transport can withhold a real response but cannot fabricate an order, fill or account result.
No normal application imports the fault package.

- `packages/fault-lab/src/scenarios.ts`

## Evidence contract

Run manifests distinguish `DETERMINISTIC_FIXTURE`, `POSTGRES_FIXTURE` and
`VENUE_OBSERVED_TESTNET`. The deterministic CLI accepts an explicit commit, epoch and seed and
writes a create-only manifest. The response-loss proxy permits only POST requests to Binance
Spot testnet order endpoints, forwards one request and exposes only the actual response status
and body digest when configured not to withhold it.

## Verification and limits

Unit tests cover all scenarios, manifest binding, exact-origin refusal, one-attempt behavior,
missing-response reservation retention and authorization-bundle recovery. Static production
surface verification rejects any app import of the fault package. These are deterministic
tests only. Real PostgreSQL concurrency, a real testnet account, actual fill behavior, the
scenario UI and the full requested mutation campaign remain unproven.
