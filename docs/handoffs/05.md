## Failure scenarios proven

Each confirmed by removing the guard, observing the named test fail, and restoring.

| Removed guard                                           | Test that failed                                                              |
| ------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Approved-origin membership check                        | hostile HTTPS origin cannot construct a reader; live host refused for testnet |
| Request-interval validation                             | a result whose interval runs backwards                                        |
| Venue identities routed through the safe-number bound   | an identity beyond the safe integer range                                     |
| Order-lookup identity requirement                       | a lookup with neither identifier                                              |
| `deferUntil` result validation                          | a defer landing outside representable time                                    |
| Centralized defer bound on the direct constructor route | negative, fractional and out-of-range durations                               |
| Cursor rollback check in the repository                 | a rollback, and the numeric comparison                                        |
| Cursor rollback trigger                                 | a rollback by a writer bypassing the repository                               |
| `COMPLETE`-has-no-unmet constraint                      | a COMPLETE cut still listing an unmet condition                               |
| Unknown open orders excluded from the verdict           | an unknown resting order on another symbol                                    |
| Filter drift excluded from the verdict                  | a changed filter during a cut                                                 |
| Bounded backfill reported as contiguous                 | the page bound reporting the window unprovable                                |
| Per-page cursor persistence                             | paging to the end and persisting as it goes                                   |

Three defects in this module's own tests were found and corrected during the round, each
recorded because the test had been passing for the wrong reason:

- an `INSERT`-path claim proved by a fixture that lacked the fields it was testing;
- a hostile-origin negative test written with `http://`, which proved the scheme rule rather
  than the origin rule and would have passed with `https://attacker.invalid` accepted;
- trade fixtures that omitted the commission scale they needed, so one asserted a success the
  design correctly refuses and another passed before reaching its own assertion.

## Real-boundary evidence

Five public, non-economic requests to `https://testnet.binance.vision`, the host
`@capitaldesk/config` allowlists for the `testnet` deployment. No credential was used, no
authenticated endpoint was called, and no order was placed, amended or cancelled. Exact
requests, responses, headers and digests are in `docs/evidence/binance-read-capability.md`.

Live rate limiting was deliberately **not** provoked: the documented penalty for repeatedly
triggering it is an IP ban scaling to three days. That handling is built from the document and
proven against a test double, and this is stated rather than glossed.

## Limitations

- **No authenticated read.** `account`, `order`, `openOrders` and `myTrades` have never been
  called with a credential. Their decoding is proven against fixtures built from the documented
  shapes; the authenticated boundary itself is unproven.
- **Reader/trader identity equality is unproven.** It needs both credentials to exist.
- **`PENDING_NEW` is quarantined, not supported.** Documented upstream, absent from module 04's
  status CHECK; adopting it is an accounting decision needing its own ADR.
- **The stream is not implemented here.** ADR-0002 conditions C1 and C5 are supplied to the
  ingest boundary by its caller, so a caller that attests them falsely gets a wrong verdict.
  The user-data stream and its session bookkeeping are later modules.
- **`MIN_NOTIONAL` has no live sample.** BTCUSDT on testnet carries `NOTIONAL`; the
  `MIN_NOTIONAL` decoding is built from the documented shape and exercised against fixtures.
- **No gap-recovery certificate producer exists.** An interrupted window is `UNSUPPORTED`, as
  ADR-0002 requires, and this module does not close one.
