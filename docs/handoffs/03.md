# Module 03 — Identity and access

**Status: COMPLETE** for the module's owned paths. No venue credential exists, so nothing here
has been exercised against Binance and no such claim is made.

## What this module establishes

Workspace membership with owner, operator and viewer roles; a closed capability set with an
explicit grant matrix; composite `(workspace, pool, strategy)` scope on every object lookup;
owner password authentication into server-side sessions; strategy-scoped agent credentials
that can propose and nothing else; and an append-only audit trail whose columns are populated
only from server-established values.

Design decisions, alternatives and limitations are in
[ADR-0012](../adr/0012-owner-authentication-and-agent-credentials.md).

## Public contract changes

- New routes, all workspace-scoped: `POST …/sessions`, `DELETE …/sessions/current`,
  `GET …/principal`, `GET …/csrf-token`,
  `POST …/pools/:poolId/strategies/:strategyId/credentials` (409 `CREDENTIAL_ALREADY_ACTIVE`
  with the live id when a key is already live),
  `GET …/pools/:poolId/strategies/:strategyId/credentials` (metadata only, never a secret),
  `POST …/credentials/:credentialId/rotations`, `DELETE …/credentials/:credentialId`.
- `CREDENTIAL_ALREADY_ACTIVE` added to the frozen reason-code set in `packages/contracts`.
- `buildServer(config, { identityPool })` turns the identity surface on. The shipped entry
  point now passes one; without it the routes do not exist.
- Migration `0002_identity` — reserved for module 03 only, as directed.
- `apps/web` build and typecheck now run through `scripts/with-env.mjs`.

## Unverified operator checklist

One behaviour has no automated proof and **has not been exercised**: the
behaviour of a real tty device. Node ships no pseudo-terminal, and adding a native PTY
dependency to prove one behaviour is a poor trade. What is proven is the suppression logic
over injected streams (`input-session.test.ts`, 5 cases, readline in terminal mode). What is
not proven, and is listed here for an operator to check rather than claimed, is:

1. From an interactive shell, run
   `DATABASE_URL=… pnpm --filter @capitaldesk/api run enroll redeem --workspace <id>`.
2. Type the enrollment code at the first prompt. It should not appear as typed.
3. Type the password at the second prompt. It should not appear as typed.
4. Run the command again and press `Ctrl-C` at the first prompt. The shell should return with
   echo working — type a character and see it.

No result is recorded for these steps because none was observed.

## Limitations

- **TOTP is not implemented.** Recorded as an open gap in ADR-0012, not as a deferred decision
  with a substitute.
- **Delivery of a one-time secret is unprovable.** The credential write is atomic; whether its
  response arrived is not a database property. Recovery is bounded and owner-visible: the
  duplicate issue names the live credential, the metadata list shows it, and rotation mints a
  new secret. The lost secret itself is gone.
- **Bootstrap trusts the database.** Anyone who can write to it can mint an enrollment code.
- **The audit boundary is exactly this.** `detail` passes a closed per-key schema;
  `actor_id`, `pool_id` and `strategy_id` come from an `AuditActor` — a principal built from
  stored rows, a member row just read, or no identity — or from a strategy tuple the same
  transaction has just confirmed. No route parameter reaches a column. What the schema cannot
  do is tell a login name from a passphrase of the same shape, and `loginName` is therefore
  never written from request input at all.
- **Rate limiting is per-process.** It slows one source and does nothing about many.
