## Public contract changes

- A configured pool binds one selected symbol, base/quote asset identities, a maximum target
  and one active policy revision. Existing pools remain unconfigured until an owner supplies
  those values; target acceptance fails closed while any binding is missing.
- `strategy_intents` retains immutable proposal content and a database-issued
  `accepted_sequence`. Partial unique indexes enforce one current target and one queued next
  cohort for each strategy and symbol.
- `intent_plan_bindings` records exact BUY or SELL base commitments. Progress counts eligible
  AVAILABLE and RESERVED claims plus unresolved commitments, so repeated evaluation cannot
  create a second demand while a child order remains open.
- `strategy_target_controls` binds defer/reinstate to the strategy target key. Its event table
  is append-only and records the owner, optimistic version and idempotency key.
- Proposal quantities and revisions are strings on the wire. Fastify coercion is disabled, so
  a JSON number cannot be converted into a seemingly valid atom string.

## Failure scenarios proven

- Missing market configuration, wrong symbol, stale policy revision, expired target, target
  over the configured maximum, zero/absent price bounds and numeric money are refused.
- Reusing an idempotency key with changed content remains a conflict after the original
  decision. The same revision with changed content cannot overwrite history.
- A sealed or in-flight pool accepts a new target as `QUEUED_NEXT_COHORT`; it leaves the
  predecessor current until the plan is terminal. Promotion refuses while a plan is active.
- Deferral survives a newer proposal and only reinstate or expiry removes it.
- Database triggers reject mutation or deletion of intent economic content and plan bindings.
- A partial result leaves the exact residual visible. Progress evaluation performs no write
  and supplies no automatic retry authority.
