# Module 04 — Transactional journal, outbox and permanent replay records

**Status: COMPLETE** for the module's owned paths. No repository method performs a network
call, and nothing here has been exercised against a venue.

## What this module establishes

Economic state that is durable and atomically replayable: an append-only ledger balanced per
asset at COMMIT; balances as a projection with one writer; immutable raw observations whose
application is a separate, idempotent act; composite venue identity; one governance lease
per authenticated account across the registry; one open epoch and one in-flight plan per
pool; a forward-only dispatch marker committed with its single-attempt outbox message; worker
leases with fencing tokens; idempotency tombstones that outlive their responses; and a restore
posture that halts, drains nothing and retains every liability.

Design decisions and their limits are in [ADR-0013](../adr/0013-transactional-journal.md).

## Public contract changes

- `@capitaldesk/db` now exports the journal repositories alongside the migrator.
- Migration `0003_journal` — reserved for module 04 only, as directed. It creates no table
  that another module owns: intents, approvals, policy versions, incidents, reconciliation
  runs and webhook deliveries arrive with the modules that define their behaviour.
- `GovernanceRepository.acquire` is the only way a pool comes into being.

## Failure scenarios proven

Each was confirmed by injecting the defect, observing the named test fail, and restoring.

| Injected defect                                         | Test that failed                                        |
| ------------------------------------------------------- | ------------------------------------------------------- |
| Deferred balance trigger removed                        | unbalanced posting refused at COMMIT                    |
| Pool row lock removed from reservation and posting      | two workers reserving under contention                  |
| Restore no longer quarantines the outbox                | both restore-posture cases                              |
| Projection write guard disabled                         | no direct write path to balances                        |
| Marker write followed by an injected failure            | no marker and no message (as designed, in-suite)        |
| Attempt bound removed from `claim`                      | a crashed holder's dispatch message is never re-offered |
| Lease-liveness removed from `fail`                      | a stalled holder's late failure report is refused       |
| Pool and plan validation removed from `mark`            | marking refused while halted, not pending, or unleased  |
| Restore no longer voids prepared attempts               | a voided attempt can never be marked                    |
| Digest comparison removed from `record`                 | changed evidence is a conflict, not a duplicate         |
| Lease acquire reads before it inserts                   | two acquirers race a lease that does not exist yet      |
| Entry-set seal removed from committed postings          | both later-append cases                                 |
| `release` compares against the original reservation     | release larger than the remainder after a fill          |
| Commit-time nonnegative guard removed                   | an over-consuming fill, and a balanced negative posting |
| `recordFill` dedupes on trade id alone                  | a changed economic field is a conflict, not a duplicate |
| Correlation conflict removed (coalesce keeps the first) | a second attempt claiming one venue order               |
| Rotation in-flight plan guard removed                   | rotation refused while a sealed plan is nonterminal     |
| Lease release no longer halts the pool                  | the pool is halted when its lease is released           |
| `sealPlan` epoch check removed                          | sealing refused against a closed epoch                  |
| `reserve` epoch check removed                           | reserving refused against a closed epoch                |
| NOT_SENT_PROVEN evidence check removed                  | refused after a send, and without complete evidence     |
| Restore back to the three pre-marker states             | EXECUTING, RECONCILING and MANUAL_REVIEW plans          |
| `maxAttempts` validation removed                        | Infinity, NaN and non-integers refused                  |
| JSON-null flag replaced by a JavaScript check           | a JSON-null response body replays                       |
| Placeholder branch deleted                              | an obvious placeholder is refused                       |

Two verifications in this round exposed defects in the verification itself: an injection that
appeared to prove the restore voiding had never been applied to the file, and the first
stale-`fail` test passed with the liveness check removed, because another worker had already
taken the message so `leased_by` alone excluded the stale holder. The injection was reapplied
and the test rewritten to model a worker resuming on its own expired lease; only then were
those guards counted as proven.

One injection did **not** fail a test and was acted on: removing the special retry for a
unique violation in the lease race changed nothing, because PostgreSQL already reports a
concurrent unique violation under SERIALIZABLE as a serialization failure. The path was
removed rather than kept as unproven surface.

## Rehearsal data

`restore.integration.test.ts` builds the state a deployment could be in when upgraded or
restored — a held reservation, a marked attempt at UNKNOWN, a partial fill on a
PARTIALLY_FILLED order, a quarantined HOUSE claim, and an unpublished message — then re-runs
the migrations and reads everything back on a fresh connection. Nothing is cleared, completed
or released.

## Limitations

- **No role-based REVOKE.** Append-only and immutable tables are enforced by triggers, which
  bind every role including the schema owner the tests run as. Revoking `UPDATE`/`DELETE`
  from an application role is a deployment control, not applied here.
- **The projection guard is a session flag.** A session that sets it deliberately can write
  `claim_balances`; the same session could rewrite the entries. It is a guard against
  application mistakes, not against a hostile database connection.
- **Lease expiry fences the database only.** A sender holding a marker can complete its send
  after its lease lapses; nothing here, or anywhere, can fence the venue.
- **Deferred tables.** Intents, approvals, policy versions, incidents, reconciliation runs and
  webhook deliveries are not created by this migration.
- **Independent deployments** that do not share this registry cannot enforce the single
  governance lease. That is a documented trust limit, not a defect this code can close.
